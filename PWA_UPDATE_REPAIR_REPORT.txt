LIFECYCLE REPAIR
1. Core readiness requires a matching generation marker and all required keys.
   Every new download and every reused entry during repair is SHA-256 checked.
   Generation-addressed execution and script/style integrity remain enforced.
2. Install/repair is shared by concurrent callers. Completion is reopened by
   cache name; one bounded retry handles a legacy worker unlinking staging.
3. Activation verifies/repairs the core before claiming clients. Navigation can
   repair missing current core, or return an actionable recovery document.
4. Failed partial downloads remain unreadable, available for a verified retry.
   No incomplete generation is declared ready or substituted with old bytes.
5. Cleanup considers only same-role caches present before installation, after
   all live controlled clients report readiness. Future staging caches are not
   swept. A worker restart loses the in-memory predecessor list and safely
   defers cleanup; it may retain extra caches until a later installation.
6. Bootstrap observes installing/waiting/active transitions and controllerchange.
   It rejects stale replies and rechecks controller identity after registration
   lookup. A new page waits for a pending successor instead of reloading back
   into a ready old controller. Startup checks control again before revealing.
7. Retry rechecks registration, calls update(), resumes waiting/current workers,
   and polls readiness/control within the existing bound. Resume verifies the
   core before skipWaiting. Concurrent retries share work. Partial execution
   requires readiness before one explicit reload; modules are not replayed.
8. Failed navigation returns HTML with Retry using registration/update/resume and
   controller readiness, rather than a terminal plain-text document. It runs no
   application modules and distinguishes offline state from an unfinished or
   failed download/preparation. No automatic reload loop is introduced.

The original 20-second handshake, 1.5-second message timeout and 15-second fetch
timeout were not increased. No navigation preload is used. The data cache is
created lazily for optional assets; absence before core readiness is valid.
